    Neu in v0.16 · Spec-getriebene Entwicklung

    Erst die Spec. Dann der Code.

    Hearth führt deinen Agenten in vier Schritten von der Idee zum fertigen Code. Jeder Schritt ist ein Dokument, das du liest und freigibst, bevor sich der nächste öffnet. Geführt, wenn du einen Coach willst, frei, wenn du den Weg kennst.

    1. requirements.md

      Anforderungen

      User Stories und Akzeptanzkriterien in EARS: WHEN … THEN the system SHALL …

      du gibst frei
    2. design.md

      Design

      Architektur, Schnittstellen, Daten, Fehler und Tests auf Basis der freigegebenen Anforderungen.

      du gibst frei
    3. tasks.md

      Aufgaben

      Kleine Programmierschritte, jeder mit den Kriterien verknüpft, die er erfüllt.

      du gibst frei
    4. ▶ Aufgabe starten

      Umsetzung

      Eine Aufgabe nach der anderen, abgehakt sobald sie steht, zum Schluss gegen jedes Kriterium geprüft.

    Mehr als eine Vorlage.

    • QualitätsprüfungNicht testbare Kriterien, fehlende Stories, offene Fragen, Anforderungen ohne Aufgabe. Zu jedem Befund gibt es „Vom Agenten beheben lassen“.
    • AbdeckungJedes Akzeptanzkriterium mit den Aufgaben, die es umsetzen, von geplant bis erledigt.
    • Erst fragenDer Agent liest deinen Code und stellt bis zu fünf Fragen, bevor er eine Zeile schreibt.
    • Drei ArtenFeature, Bugfix mit Regressionsschutz, Refactoring mit dem, was sich nicht ändern darf.
    • Geführt oder freiEin Coach mit Checklisten oder alle Dokumente auf einmal. Umschalten jederzeit.
    • Dein AgentClaude Code, Codex, Copilot, OpenCode oder Gemini, in der Sandbox. Specs sind einfaches Markdown im Repo, .kiro/specs geht auch.

    Agent Hooks hüten das Feuer.

    Endet ein Durchgang, schaut Hearth, was der Agent geändert hat, und führt deine Hooks aus: einen Auftrag an den Agenten oder einen Befehl in der Sandbox.

    • Agent speichert \.swift$„Passe die Tests für diese Dateien an und führe sie aus.“
    • Agent speichert \.tsx?$npm run lint in der Sandbox. Schlägt es fehl, geht die Ausgabe zurück an den Agenten.
    • Agent beendet seinen Durchgang„Prüfe deinen Diff auf Fehler, fehlende Tests und Reste.“
    • Agent ändert requirements.md„Bring Design und Aufgaben wieder in Einklang.“

    Hooks können sich nicht aufschaukeln: Ein Durchgang, den ein Hook gestartet hat, löst nie Hooks aus. Eine Hook-Datei aus einem Repository oder vom Agenten läuft erst, nachdem du genau diesen Inhalt erlaubt hast. Kiros .kiro/hooks werden mitgelesen.

    Was im Ring bleibt.

    Hearth startet jeden Agenten in einer nono-Sandbox (macOS Seatbelt). Innerhalb des Rings arbeitet er frei:

    • ~/dein-projekt lesen und schreiben
    • seinen eigenen Einstellungsordner in Hearth
    • LLM-APIs, npm, PyPI, Maven
    • GitHub, GitLab und Dokumentation

    Draußen bleiben:

    • SSH-Schlüssel

    • Shell-Konfiguration

    • Cloud-Zugangsdaten

    • Cookies, Passwörter, Sitzungen

    • der Rest deines Home

    • jeder nicht freigegebene Host

    Weitere Domains, Ports und Ordner gibst du in den Einstellungen frei. API-Keys reicht nono als Platzhalter durch: Der Agent sieht nie den echten Wert.

    Deine Agenten, deine Logins.

    Hearth bringt kein eigenes Modell mit. Es hält die Agenten in Schach, für die du schon bezahlst.

    • Claude Codedein Claude-Abo, über die offizielle CLIStatus per Hooks in der Inbox
    • CodexChatGPT-Login oder API-KeyStatus per notify
    • GitHub Copilot CLIdein GitHub-Kontoim Terminal-Chat
    • OpenCodejeder Anbieter, den OpenCode kenntmit privatem Server in der Sandbox
    • Gemini CLIdein Google-Kontoim Terminal-Chat

    In drei Zügen entfacht.

    Kein Konto, keine Konfiguration. Hearth bringt die Sandbox mit, deine Agenten bringst du selbst.

    1. 1

      Installieren

      Der Befehl oben lädt die App, prüft die SHA-256-Prüfsumme und legt sie in den Programme-Ordner. Updates kommen aus der App.

    2. 2

      Ordner wählen

      Der Projektordner ist das Innere des Rings: Nur hier darf der Agent schreiben.

    3. 3

      Agent starten

      Claude Code, Codex, Copilot, OpenCode oder Gemini – mit deinem eigenen Login, im Terminal der Chat-Ansicht.

    Alle Feuer in einem Fenster.

    Eine Inbox zeigt, welcher Agent arbeitet, wartet oder fertig ist. Daneben Ordner, Git, Editor, Tests und Builds – die auch in der Sandbox laufen.
